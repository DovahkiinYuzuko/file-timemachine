# 設計仕様書: GitGraphの組み込みとフォルダ初期化連動

* **作成日**: 2026-05-20
* **作成者**: アビー (AIアシスタント)
* **トピック**: GitGraphのMainLayoutへの組み込みとプロジェクトパス連動

## 1. 目的
`app-file-timemachine` アプリケーションにおいて、仮置き（Placeholder）のままになっていたGitグラフ（路線図）表示エリアに `GitGraph` コンポーネントを正しく組み込みます。また、選択されたプロジェクトのパスと表示を連動させ、Git管理されていないフォルダの場合はその場で初期化（履歴保存の開始）ができるようにUIとバックエンドコマンドを繋ぎ込みます。

## 2. 設計詳細

### A. 画面の状態遷移とUI表示

プロジェクトの選択状態およびGitの履歴有無に応じて、画面中央上部の路線図表示エリアは以下の3つの状態に遷移します。

1. **フォルダ未選択状態 (`projectPath === null`)**
   - **表示**: 案内メッセージ「フォルダを開いてタイムマシンを開始しよう」を表示します。
   - **理由**: アプリ起動直後など、作業対象のフォルダが選択されていないため、アクションを促します。

2. **履歴未存在状態 (`commits.length === 0`)**
   - **表示**: 「履歴が見つかりませんでした」というテキストと、ボタン「履歴の保存を開始する」を表示します。
   - **理由**: Git未初期化のフォルダ、または初期化したてで最初の保存（コミット）を行っていないフォルダです。
   - **挙動**: ボタンがクリックされた場合、以下の初期化シーケンスを自動実行します。
     1. Tauriコマンド `git_init` を呼び出し、リポジトリの初期化と `.gitignore` の自動生成を行います。
     2. Tauriコマンド `git_commit` を自動的に呼び出し、メッセージ「最初の保存」で現在のファイルを記録します。
     3. 成功後、親コンポーネントに通知して画面を再描画します。

3. **履歴存在状態 (`commits.length > 0`)**
   - **表示**: `@gitgraph/react` を用いたコミット履歴の路線図を描画します。
   - **理由**: 過去の履歴が存在するため、視覚的に変更点を確認できるようにします。

### B. コンポーネントのインターフェース変更

#### `GitGraph.tsx`
* **Props定義**:
  ```typescript
  interface GitGraphProps {
    projectPath: string | null;
    refreshKey?: number;
    onInitSuccess?: () => void;
  }
  ```
* **依存性の変更**: `useEffect` の依存配列に `projectPath` と `refreshKey` を含め、これらが変更された際に再読み込みが走るようにします。

#### `MainLayout.tsx`
* コメントアウトされていた `GitGraph` のインポートを解除します。
* プレースホルダー `<div>(Git Graph Placeholder)</div>` を以下のように書き換えます。
  ```typescript
  <GitGraph 
    projectPath={projectPath} 
    refreshKey={historyRefreshKey} 
    onInitSuccess={() => setHistoryRefreshKey(prev => prev + 1)} 
  />
  ```

## 3. 安全設計・エラーハンドリング
- 初期化および初回コミット処理中にエラーが発生した場合は、エラー状態をコンポーネント内に保持し、ユーザーにエラー内容を赤色で分かりやすく通知します。
- 非同期処理中はボタンを無効化（disabled）にし、二重実行を防ぎます。
