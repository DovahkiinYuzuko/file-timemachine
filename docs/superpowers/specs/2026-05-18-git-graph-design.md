# Gitグラフ描画 (Git Graph) デザイン仕様書

## 概要
ファイルタイムマシンのルート管理（ブランチの可視化）機能。
「Gitを意識させない」というコンセプトと、「歴史の繋がりを知りたい」というニーズを両立させるため、ユーザーがUI上でグラフの表示スタイルを切り替えられる**「ハイブリッド・グラフ」**を採用する。

## 1. アーキテクチャ＆コンポーネント
*   **対象コンポーネント**: `src/components/graph/GitGraph.tsx` （既存のプレースホルダーを本格実装に書き換え）
*   **役割**: Rustから取得したコミット履歴を元に、SVGベースの分岐グラフを描画する。
*   **ライブラリ**: `@gitgraph/react`

## 2. デザインモード（表示スタイル）
コンポーネント内に状態 `graphStyle` (`"tree" | "metro"`) を持たせ、以下の2つのモードをトグルボタンで切り替える。

### モードA: 🌳 ツリー形式 (Branch Mode)
*   **コンセプト**: 「ここから分岐した」という時間の流れを正確に伝えるスタイル。
*   **テンプレート**: 線の枝分かれと合流が明確に描画される標準的なテンプレート（またはBlackArrowベース）。
*   **用途**: 過去の経緯や、いつどこから「お試し案」が作られたかを確認したい時。

### モードB: 🚇 路線図形式 (Parallel Mode)
*   **コンセプト**: 「A案」「B案」といった結果だけをシンプルに平行線で並べるスタイル。
*   **テンプレート**: `@gitgraph/react` の `Metro` テンプレートをカスタマイズし、極力線の交差を減らした直線的な描画を行う。
*   **用途**: 現在進行中の「お試し案」がいくつあるのか、スッキリと俯瞰したい時。

## 3. UI/UX コンポーネント構造
*   **ヘッダー/ツールバー**: グラフの上部（または右肩）に、モード切り替え用のトグルボタン（例：`[🌳 ツリー] [🚇 路線図]`）を配置。
*   **グラフ領域**: 選択されたモードのテンプレートを適用した `Gitgraph` コンポーネントを描画。
*   **インタラクション**: グラフ上のコミットノード（丸い点）をクリックした際、そのコミットの詳細や状態をプレビューエリア等に反映させる準備として、`onMessageClick` などのイベントハンドラを実装する（実際の連動は別タスク）。

## 4. データフロー
1.  **データ取得**: `MainLayout` と同様に、Tauriの `invoke("git_log", { path: projectPath })` を呼び出し、`CommitLog[]` を取得する。
    *   *注: 完璧なグラフを描画するには、将来的に各コミットの親(parent)や所属ブランチの情報が必要になるが、現在の `git_log` は一本道のログしか返さない。今回のタスクではまず「描画の枠組みと切り替えUI」を完成させ、ダミーデータまたは一本道のデータでスタイル切り替えが機能することを確認する。*
2.  **描画**: 取得したログ（またはモックデータ）を `@gitgraph/react` のAPI（`branch.commit()` など）に流し込み、グラフを生成する。

## 5. エラー・空状態のハンドリング
*   **空状態**: 履歴がない場合は `common.placeholder.no_history` を表示。
*   **エラー**: 取得エラー時は `common.error.failed_to_fetch_logs` を表示し、裏でロギングする。

## 6. アクセシビリティ (A11y)
*   SVGコンテナには `role="img"` と適切な `aria-label` を付与する。
*   スクリーンリーダー向けに、グラフの構造をテキストリスト（`<ul><li>`）として視覚外（`.sr-only`）にレンダリングし、同等の情報を提供する。

## 7. Scope Check & Ambiguity (セルフレビュー結果)
*   **Scope**: 今回のスコープは「切り替え可能なグラフUIの構築と描画」である。バックエンドの `git_log` を拡張して複雑なブランチ構造を取得する部分は、Rust側の重い改修が必要になるため、本タスクの「グラフ描画基盤の構築」とはスコープを分離し、まずはダミーデータ等を用いてUI/UXを完成させる方針とする。
*   **Ambiguity**: `@gitgraph/react` は命令的に分岐を描画するライブラリであるため、動的なコミットログからの自動構築アルゴリズムが必要になる。このアルゴリズムの完全な実装は複雑になるため、本タスクでは基本的な描画ロジックの骨組みを組むことに集中する。
